# UI на SVG

Одна из ключевых гипотез проекта: **весь** UI — не только иконки, а и окна, подложки, кнопки, бары — собирается из SVG-элементов. Документ описывает, как мы это делаем и почему именно так.

## Зачем

- Единый визуальный язык с игровой графикой.
- Бесшовное масштабирование под разные разрешения без артефактов.
- Состояния (hover, pressed, disabled, focused) выражаются как параметры одного и того же шаблона.
- Темизация: смена палитры → автоматическое перерисовывание всего UI.

## Где живёт код

```
src/ui/
  UISvgKit.js              // фасад: makeButton, makeWindow, makePanel, makeBar, ...
  svg-templates/
    button.js              // функция (params) -> string SVG
    window.js
    panel.js
    hud-bar.js
    icon-heart.js
    ...
  components/
    SvgButton.js           // Phaser-обёртка: контейнер + интерактивность + состояния
    SvgWindow.js
    SvgPanel.js
    HudBar.js
```

## Как именно рендерится SVG-элемент

1. Шаблон — это функция: получает параметры (`width`, `height`, `label`, `variant`, `state`, цвета из палитры) и возвращает строку SVG.
2. Из строки получаем `Blob` с MIME `image/svg+xml`, оборачиваем в `URL.createObjectURL`, грузим в `Image`.
3. После `image.onload` рисуем картинку на `HTMLCanvasElement` нужного размера.
4. Регистрируем канвас в текстурах сцены: `this.textures.addCanvas(key, canvas)`.
5. Создаём `Phaser.GameObjects.Image` с этой текстурой.

`SvgTextureFactory` кэширует ключи: одинаковый набор параметров → один и тот же ключ → одна текстура в памяти.

> На случай, если канвас-подход даст проблемы с резкостью при ретине — у фабрики есть параметр `dpr`, и она запекает текстуру с учётом `window.devicePixelRatio`.

## Состояния кнопки

Кнопка — это `Container`, в котором лежит изображение текущего состояния и `zone` для интерактивности.

Состояния и их триггеры:

- `idle` — базовое.
- `hover` — `pointerover`.
- `pressed` — `pointerdown` (визуально утоплена / подсвечена).
- `disabled` — установлено флагом, не реагирует на ввод.
- `focused` — для управления с клавиатуры (стрелки в меню).

При смене состояния `SvgButton` просто меняет текстуру у внутреннего `Image` на ключ соответствующего состояния. Тексты лейблов могут рендериться двумя способами:

- **Как часть SVG** (через `<text>` в шаблоне) — идеально стилистически, но требует доступа к шрифтам в SVG-рендере.
- **Как отдельный `Phaser.Text` поверх SVG-подложки** — проще и более кросс-браузерно. Используем этот вариант по умолчанию.

## Окна и модалки

Окно (`SvgWindow`) — это:

- Подложка (один большой SVG с тенью/обводкой/градиентом). Если окно меняет размер — мы либо перегенерируем SVG с новой шириной/высотой, либо делаем 9-slice вариант (по необходимости).
- Заголовочная зона.
- Контентная зона (`Container`, в который складываются дочерние компоненты).
- Опционально — кнопка закрытия.

## HUD

HUD — это отдельная сцена `HUDScene`, идущая поверх `GameScene`. В неё кладутся:

- Бар здоровья (`HudBar`) — SVG-фон + SVG-заполнение.
- Индикатор уровня оружия (1..N).
- Счёт и множитель.
- Иконки бомб/щитов.
- HP-бар босса (появляется при появлении босса).

Все HUD-компоненты подписаны на события из `EventBus` (например, `player:hp-changed`, `score:changed`, `weapon:level-changed`, `boss:spawned`, `boss:hp-changed`).

## Меню и стартовый экран

Иерархия сцен:

- `MainMenuScene` — заголовок, кнопки «Играть», «Уровни», «Настройки» (на будущее). Всё — `SvgButton`.
- `LevelSelectScene` — сетка карточек уровней. Карточка = `SvgPanel` + иконка + текст + состояние «заблокирован/открыт/пройден» (визуально разные SVG-варианты).
- `PauseScene` — модалка поверх `GameScene`.
- `GameOverScene` и `VictoryScene` — модалки с итогами.

Навигация по меню работает и мышью, и клавиатурой. Подсветка `focused`-состояния обязательна для клавиатурного использования.

## Производительность

Потенциальные риски и стратегии:

- **Слишком много уникальных текстур.** Митигируется через кэш в `SvgTextureFactory`: только реально различающиеся параметры дают новую текстуру.
- **Перегенерация во время боя.** Запрещаем создание новых SVG-текстур в `update()` геймплейных сущностей. Все нужные состояния (idle, hit, damaged) пред-генерируются в `PreloadScene`.
- **Большие SVG-окна.** Делать их разумно простыми: 1–2 прямоугольника, обводка, тень. Никаких сложных фильтров.
- **Ретина.** Текстуры запекаются с учётом DPR.

## Тестирование UI без игры

В отладочной сборке предусматриваем сцену `UIShowcaseScene` (опционально), которая просто показывает все компоненты во всех состояниях. Это даёт быстрый цикл итераций по визуалу без необходимости заходить в бой.
