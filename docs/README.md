# Sky Rider — First Strike. Документация проекта

Сборник проектных документов. Цель документации — зафиксировать концепцию, геймдизайнерские решения и архитектурный подход до того, как мы начнём строить каркас игры. На все вопросы «как мы это делаем» в коде ответ должен быть здесь.

## Краткая суть игры

Вертикальный shoot 'em up в космосе. Игрок управляет небольшим истребителем, который летит «вверх по экрану», а навстречу ему движутся враги двух классов:

- **Нижний слой** — фоновые цели, с которыми нельзя столкнуться, но их можно отстреливать ради очков и бонусов. Визуально они «под» игроком.
- **Верхний слой** — основные противники: летят на игрока, могут стрелять, могут столкнуться.

Базовый цикл: маневрировать, стрелять, собирать апгрейды оружия, доходить до босса уровня.

## Технологический стек

- HTML + [Phaser 4](https://phaser.io/) (через CDN, версия зафиксирована в `index.html`) — **только игровой мир** на canvas: фон, юниты, снаряды, эффекты, всё, что относится к геймплею.
- Поверх игрового canvas — **отдельный UI-viewport** того же размера: счётчики, панели, окна, меню, HUD и любой интерактив экранного уровня. Внутри игрового canvas эти элементы не рисуются (допустимы лишь чисто игровые всплывающие подсказки вроде урона в мире, если это заложено геймдизайном).
- Чистый JavaScript (ES modules в `src/`).
- Визуал (UI и враги) — **SVG-файлы в `assets/`**, не зашитые строки в JS; правки делаются в файлах, затем ассеты подключаются в рантайме. Способ использования (DOM, запекание в текстуру Phaser, предзагрузка и кэш) — на усмотрение UI Toolkit / Game Toolkit.
- Локальный запуск через `python scripts/serve.py` (см. корневой README).

## Принципы, которыми мы руководствуемся

1. **Конфиг важнее кода.** Враги, волны, оружие, уровни — описываются данными, а не хардкодом в сценах.
2. **Слабая связанность через события.** Системы общаются через шину событий, а не лезут друг в друга напрямую.
3. **Один источник правды для визуала.** Палитра, размеры и формы лежат в одном месте; ни сцена, ни сущность не выдумывают свои цвета.
4. **Два вида «экрана».** **World view / game view** — Phaser-canvas со сценой и игровой логикой. **Screen view / UI view** — слой поверх canvas того же размера, где живёт весь интерфейс и интерактив вне мира.
5. **SVG — файлы в ассетах.** Иконки, кнопки, подложки, окна и **все враги** хранятся как отдельные `.svg` в репозитории, чтобы их можно было открыть, отредактировать и версионировать независимо от кода. Встраивание SVG в JS как длинные строки — не целевой подход. При старте игры ассеты можно подгружать, кэшировать или конвертировать в формат, удобный движку — это решает соответствующий toolkit.
6. **Маленькие сцены, большие системы.** Сцена — это «оркестратор», а логика живёт в переиспользуемых системах.
